## Why

A seven-part review on 2026-10-19 found working parts inside a weak structure:

- One mutable `Director` owns scene, timeline, media, caches and export. Frames render serially, and editors or servers have no session object to hold.
- The static-subtree cache never fires on HTML scenes. Decode and encode stream raw RGBA through FFmpeg pipes, and video seek is keyframe-inaccurate.
- Seven authoring formats compete. Rhai exposes about 250 functions with a catalog of about 30, and misspelled effects, transitions and properties fail silently.
- `director-html` stringifies typed Lightning CSS values and reparses them in a 2,400-line `match`.
- The repo has no golden images, clippy is red, CI runs only by hand, and benchmarks measure box grids.

Director's defensible advantages: it is the only native engine that compiles HyperFrames-style HTML, edits need no compile step, and output is browser-free and deterministic. FFrames already matches the agent CLI, so agent tooling alone does not differentiate.

## Target architecture

Build new crates beside the current core, port features over, then delete the old `Director` (strangler migration).

| Layer | Crate | Owns |
| --- | --- | --- |
| Scene document | `director-scene` | Serializable scene data with no Skia: a node data enum, property channels and keyframes, one effect and transition table, asset references, generated JSON schema, patch by stable id. |
| Frontends | `director-html`, timeline JSON, optional Rhai | Compile into the scene document. HTML/CSS is the primary front door. GSAP timelines compile to native keyframe tracks. Captures become an import path. Rhai becomes an optional generator over the host API. |
| Renderer | `director-render` | Pure `(scene, time) -> display list`, Skia paint on worker-owned surfaces, a content-hash layer cache that works for HTML, a media frame server with accurate seek, and an encoder path without full RGBA round trips. |
| Host session | `director-host` | Open, patch, inspect, render frame, export, revision and cancellation. The CLI, an MCP server, a future Tauri editor and serverless workers link it. |

Keep and port: the track timeline model, generational node ids, pure animation evaluation, layout-cache keys, required-font checks, the caption engine, active-speaker reframing, and the director-html parsing, cascade and paint knowledge.

Freeze: Lottie (no new features; ThorVG is the option if Lottie becomes headline), SMIL beyond what Hyper CN needs, and the Paper Shader translator.

## Phases

Each phase ends with its gate green and a commit. Phases 2 to 4 run in order; the typed computed style in phase 5 may start once phase 1 lands.

### Phase 1: Safety net and pruning

- Delete `director-pipeline`, `specs/`, `WgpuNode`, the `preview_frame`, `contact_sheet`, `verify_lottie` and `review_visuals` bins, the browser player page, HTTP fetch inside scripts, and examples that only demo removed or gimmick features.
- Fix the example walker: commit or remove missing assets, remove live network access and machine-specific paths, and stop parallel tests from racing on `set_current_dir`.
- Fail loud: unknown effects, transitions and properties return errors. Generate the authoring catalog from the registered surface.
- Commit a golden corpus of about 40 scene frames with a perceptual diff and fonts that resolve regardless of working directory.
- Make clippy green, run CI on push with a Linux job, and remove dead dependencies and the empty `mock_video` feature.
- Fold in the plan 09 close-out re-runs listed under Stale checks.

Gate: `cargo test --workspace --release` and `cargo clippy --workspace --all-targets --release -- -D warnings` pass locally and in CI, and the golden corpus fails on a deliberate one-pixel change.

### Phase 2: Scene document

- `director-scene` with the node data enum, property channel table, effect and transition table, keyframes and serde plus schemars.
- An exporter from the current `Director` so the golden corpus can round-trip through the document.

Gate: every golden scene round-trips through `director-scene` JSON without loss.

### Phase 3: Parallel renderer

- `director-render` evaluating the document per frame, painting on a worker pool, with the layer cache, media frame server and new encoder path.
- Delete the old `Director` render path once parity holds.

Gate: golden corpus parity with the old core, and a measured end-to-end 1080p HTML export speedup recorded in the table below. **Met 2026-10-25.**

### Phase 4: Host session and agent surface

- `director-host` with patch, revision and cancellation; the CLI becomes a thin client. Landed: the session, patch ops, cancellable export, input loading, reload, cached audio, GPU frames and native project edits; every top-level CLI command that opens an input runs on `Session`, and `Input::load` is gone; `outline` and `diff` print JSON and the error envelope, and the diff carries the patch between two inputs; `director-engine mcp` serves the session to agents as MCP tools, and `director-engine skills` generates the `director-mcp` skill from their schemas; `Session::qa` scores a revision for publishing through `director-engine qa` and the MCP `qa` tool; `director_host::Editor` serves the editor protocol in-process and `director-engine editor` serves it over stdio with a frame ring file; MCP hardening (2026-10-26): the `node` tool reads records and settable pointers, `diff` sets a changed color as one op, outputs stay inside allowed roots (`--allow-dir`), `qa` and `export` send progress notifications, logs are plain `warn` and FFmpeg prints errors only, and exports without audio tracks carry no audio stream.
- An MCP server mode, generated skills, and `outline`, `diff` and QA-score commands with one JSON error envelope.
- An editor protocol: shared-memory frames, generation cancel, windowed audio and an edit and seek control plane.

Gate: an agent can open, patch, inspect and export a project through MCP alone. **Met 2026-10-25.**

### Phase 5: Authoring

- Typed `ComputedStyle` plus a property table in `director-html`; split element paint. Landed: the property table, `ComputedStyle`, element paint split into `element/{mod,background,borders,text}.rs`, a cascade that carries typed values and reparses only `var()` values, and typed layout, background, border, box, effect, transform and text groups in `style/`.
- Timeline JSON for motion over HTML visuals. Landed: `director-timeline/1` keyframe tracks in a `<script type="application/director-timeline+json">` compile to native animations on elements by id, with CSS easing per segment, and export as scene `CssAnimation`s; `examples/html/timeline-motion.html` exercises it.
- GSAP to native keyframe tracks. Landed: the real GSAP library runs at compile time in the `director-recorder` helper process on V8 against a Rust-owned DOM whose layout reads come from a native probe compile; the compiler seeks every frame, bakes constant results into the HTML and turns varying styles into frame-sampled `director-timeline/1` tracks in transform component channels. Keyframes, `transformOrigin`, stagger `ease` and `grid`, callbacks and function values follow GSAP itself; `textContent` becomes text tracks and SVG motion, DrawSVG and MorphSVG included, becomes native SMIL; MotionPath `align` and `autoRotate` measure through viewBoxes and CSS transforms; `filter` tweens become per-function channels, `box-shadow`, `text-shadow`, `background-position`, `background-size` and `clip-path` tweens become per-field and per-corner channels, border colors and widths become per-side channels, `font-size`, `letter-spacing`, `word-spacing`, `font-stretch`, per-axis `font-variation-settings` and `line-height` relayout the element's text and reach the descendants that inherit them, `padding` and `margin` become per-side layout channels, sets hold until their exact time on tracks and SVG SMIL, motion blur samples GSAP at the shutter times between frames, and running `@keyframes` win over GSAP on a shared property; `director-engine html timeline` prints the tracks; `examples/html/gsap-motion.html` and `examples/html/motion-path.html` exercise it.

Gate: the Hyper CN corpus compiles through the typed style path with no new refusals, and a GSAP fixture set renders as native tracks. **Met 2026-10-27**: the corpus half on 2026-10-26, and the `tests/fixtures/gsap` set renders as native tracks in `tests/gsap.rs`.

### Phase 6: Proof and media quality

- A public benchmark harness against HyperFrames, FFrames, Remotion and raea (needs the user's explicit yes before running).
- Motion blur on every paint path, 10-bit and HDR export, LUFS normalization and ducking.
- Export QA on painted pixels, the mix and the transcript, as errors, warnings and info with a fix, in `Session::qa` and on a finished MP4 ([plan 11 C2](11-transcription-and-competitive-gaps.md#part-c-raea-comparison)). Landed in `Session::qa` 2026-11-05, each with a failing and a passing fixture:
  - caption contrast of at least 3:1 against the pixels behind each glyph, at the scanned frame nearest the caption's middle;
  - reading time of about 0.3 s a word and at least 1 s, waived for captions the voice reads while they show;
  - captions and word-tied cues starting on the first word they carry, from the transcript's word times;
  - the voice against its bed: music under speech at least 12 dB down, and no voiceless stretch louder than the voice's median (the pass condition for ducking);
  - dead stops: a steady bed that drops 12 dB or more within 20 ms and stays down instead of fading;
  - encoder blotching: with a finished export (`--video`), block steps in its dark flat areas against the painted frames at the 0.5 s steps. The draft encode (x264 ultrafast, CRF 30) of a dark gradient fails and the final encode passes; on the showreel the final software and NVENC encodes pass and an ultrafast CRF 30 re-encode flags 12 of 31 frames.
  - finished files without the project (`qa_video`, `qa` on an MP4, MCP `qa_video`): static stretches on decoded frames, and loudness, peak, clipping, dead stops and, with words, the voice against bed on the first audio stream.
- Still open for C2: project rules (mechanical checks a project declares, failing as errors).
- Colour grading (issue 10), landed 2026-11-05: `.cube` 3D LUTs (2 to 65 points) and six presets on any element or the whole frame through `--grade`, with `--grade-mix` crossfades and `--grade-intensity` animatable from `@keyframes`, timeline JSON and GSAP, applied to encoded sRGB/BT.709 values and round tripping through the scene document. `examples/html/colour-grades.html` shows every preset and a 1 s crossfade.
- Real 3D (issue 9), engine spike 2026-11-05 in `spikes/engine-3d/`: Filament 1.80, Bevy 0.20 and Three.js r185 rendered the same Blender GLB (bevelled type, chrome, plastic, clearcoat and glass spheres, emissive ring, monkey head, sun and spot light, animated camera) under forest IBL with shadows and bloom, with a Skia 2D layer composited on the same GPU. Numbers are in the measurement table.
  - Filament is fastest: 1.05 ms a 1080p frame and 2.44 ms at 4K including the Skia composite, about a fifth of Bevy at 1080p and a third at 4K, and it boots in 240 ms against Bevy's 730 ms. Skia runs on Filament's own Vulkan device. Filament's headless swapchain images lack SAMPLED usage, so the spike copies each frame into a Skia texture on the GPU; the copy sits inside the 0.19 ms composite.
  - Three.js renders in 1.80 ms at 1080p and 5.00 ms at 4K, then pays a full-frame `readPixels` (1.10 ms and 6.50 ms) plus the hop out of the browser process. CDP screenshots cost 266 ms and 892 ms a frame. JavaScript stays in `director-recorder`, so every Three.js frame would cross a process boundary.
  - Bevy works on a shared device with zero copies through wgpu-hal handles, at 5.36 ms (1080p) and 8.05 ms (4K).
  - Decision: Bevy, in a new `director-3d` crate. Director must render anything raea covers (photoreal scenes, Gaussian splats, matchmoved footage), so capability breadth outranks per-frame cost, and every candidate already exports a 4K frame in under 10 ms. Bevy extends in Rust and WGSL, has ray-traced lighting, atmosphere and volumetric fog, and shares Skia's Vulkan device with zero copies. Filament adds features only in C++ inside its own engine.
  - One engine serves three quality levels on one scene: Live (real-time Bevy for editing, scrubbing and agent checks), Export (the same scene with many jittered samples averaged per frame) and Hero (a path tracer on RTX hardware, previewed progressively). Preview and export render the level a scene asks for, so they match pixel for pixel at each level. A second engine for preview stays out, because its shading would differ from export.
  - The Filament spike stays in `spikes/engine-3d/filament/` as the speed reference for `director-3d`.
  - Slice 1 (2026-11-06): `crates/director-3d` runs one headless Bevy 0.20.1 app on its own thread and paints glTF scenes as `ModelNode`. HTML `<model src="scene.glb">` takes an environment probe, exposure, background and loop attributes; its clips run on the element clock and `--camera-yaw`, `--camera-pitch` and `--camera-distance` orbit the file's camera from CSS, keyframes and GSAP. The scene document records a `NodeBody::Model`, and a document render matches the live preview pixel for pixel.. Bevy adds 1.2 GB to `target/release` (1.8 GB with wgpu, naga and helper crates), its cold build takes about 2 minutes, and `director-engine.exe` grows from 57.5 MB to 119.7 MB.
  - Slice 2 (2026-11-06): Bevy and Skia share one wgpu Vulkan device. `director-3d` opens it with up to 8 queues in family 0, Bevy renders on queue 0, and `director_3d::gpu_context()` gives each Skia context a spare queue; `director-cli` asks it first. On such a canvas a model frame stays a `VkImage` in shader-read layout that Skia samples in place, and the result matches the CPU readback pixel for pixel. A studio lease spans each shot until Skia has sampled it, and each target refilms only when a shot input changes.
  - Slice 3 (2026-11-06): the Export level. `<model samples="N">` renders each frame N times with Halton sub-pixel camera jitter and averages the renders in linear light on the GPU, which removes the stair steps SMAA leaves on long edges. Preview and export use the same count, and the scene document records it. Live stays at one sample.
  - Slice 4 (2026-11-06): skinning and morph targets. `crates/director-3d/tests/fixtures/rig.glb` holds a skinned column that bends and a ball whose morph target squashes it, both on the element clock. Bevy 0.20 drops a hidden stage's mesh instances and brings a morph mesh back without its morph descriptor, so `director-3d` marks morph meshes changed on each shot and steps once more after a stage switch.
  - Slice 5 (2026-11-06): depth of field. `--camera-aperture` (f-number) and `--camera-focus` (metres, `auto` at the scene centre) make the camera a thin lens: at least 16 renders move the eye across the aperture and shift the image so the focus plane holds still. Preview and export render the same samples. Bevy's bokeh pass was rejected because it writes opaque alpha and its pipeline arrives a few frames late.
  - Slice 6 (2026-11-06): soft shadows and area lights. `<light>` children of `<model>` add sun, point, spot and rect lights to the document's `ModelBody`. A light with an emitter size averages 16 or more renders lit from points across its disc, rectangle or sun angle, which gives true area-light penumbrae with the same frames in preview and export. Bevy's PCSS (a noisy heuristic keyed to the frame count) and its LTC rect lights (no shadows) were rejected.
  - Slice 7 (2026-11-06): Gaussian splats. `<splat>` children of `<model>` place 3D Gaussian splat `.ply` captures beside the glTF meshes, or alone with no `src`, through `bevy_gaussian_splatting` 9.0.0 and its GPU radix sort per view. The document records each cloud as an `application/x-ply` asset with its placement. Sample jitter moved from `TemporalJitter` to a `SubCameraView` offset, because the splat shader reads the unjittered projection. Splats draw after tonemapping, since the captures carry their camera's tone curve, so the meshes beside them keep the filmic curve. The crate forces `bevy_winit` and its audio, UI and picking crates into the build.
  - Slice 8 (2026-11-06): the Hero path tracer. `<model paths="N">` path traces each sample with N paths per pixel through `bevy_solari` 0.20.1's hardware ray traced scene and a Director compute pass, then tonemaps and averages it like the raster levels, so preview and export match and a frame depends only on its inputs. Point and spot lights (the file's and the authored ones) are sampled in the pass with shadow rays in Bevy's raster units, rect lights trace as emitting quads, and each lands where the raster light does at 1.0 to 1.1 times its strength on the directly lit patch; skins and morph targets deform on the CPU into the traced copies. Splats draw over the traced image in the transparent pass against the raster depth, and a model made only of splats rasterizes. Solari's own realtime pipeline (ReSTIR with a denoiser) was rejected because its temporal reuse changes a frame with the frames before it.
  - Slice 9 (2026-11-06): the Blender round trip. `make_model.py --eevee` renders the scene behind `model.glb` in Blender 5.2's Eevee under a shared elevation-only sky, and `tests/eevee.rs` paints the GLB at matching units (log2(683 / 1.2) EV100, a 683 cd/m² probe). The Live, Export and Hero frames cover the same pixels as Eevee (IoU 0.998 to 1.000), correlate in luma at 0.94 to 0.96, and come out 7 to 11 % darker through TonyMcMapface against Blender's Standard transform.
  - Slice 10 (2026-11-06): matchmoved footage. `<model shadow-catcher="Ground">` turns the named glTF nodes' meshes into shadow catchers: a material that lights a white diffuse surface with and without each light's shadow map, adds the ambient and probe light to both, and writes black at alpha 1 - r^(1/2.2) so a display-encoded plate darkens as far as the real ground would. It draws in the transparent pass, so it works over the Hero image and stays out of the ray traced scene. A shot over a transparent sky no longer blooms, because the layer's glow hazed the page under it. `make_track.py` renders a plate (a checkered ground with the box hidden, as H.264) and Eevee's ground truth with the box, and exports the box, the ground stand-in and the solved camera as `track.glb`. The `<video>` plate under the model lands the box on Eevee's at IoU 0.97 to 0.99 and its shadow at IoU 0.90 to 0.93, darkens the plate to 0.82 of its luma against Eevee's 0.81 to 0.82, cuts the mean error against the ground truth from 4.5 to 6.7 levels (the bare plate) to 1.5 to 2.0, and changes the plate elsewhere by 0.7 levels.
  - Slice 11 (2026-11-06): extruded type. `<text3d>` inside `<model>` builds one line of real mesh type: Skia's HarfBuzz shaper and path ops give the outline at the font's `wght` and `wdth` positions, Lyon triangulates the faces, and chamfered walls close the solid with outward normals (volume equals outline area times depth within 0.1 %, outline area within 1 % of Skia's fill). Fonts come from a file or from `font-family`, weight and style through Director's font collection. The faces and sides take their own PBR materials, the type exports into the scene document with its font as an asset, and the Hero level traces it (IoU 0.965 against the raster). A Hero stage without a sun or an emissive mesh gets a dark sun, because Solari traces nothing without one. Camera pitch no longer clamps at 89 degrees, so a full turn comes back to the front (IoU 1.000), and the framing camera's near plane follows the orbit distance. Film shot s03 swaps its 18 stacked CSS planes for `<text3d>` Archivo 900 at 108 % stretch, with GSAP's rotationX and rotationY on the model's camera.
  - Slice 12 (2026-11-06): reflections on the plate. `<model shadow-catcher="Floor" reflection="R">` mirrors the model in flat catchers: each stage fits a plane to its catcher triangles, and a mirror camera (the Director camera reflected in that plane) renders linear radiance into a half-float image that the catcher samples with Schlick's Fresnel at F0 = R, over the shadow it already casts. On `mirror.glb` a full mirror lands the type where a copy turned 180 degrees about X stands (IoU 0.981, luma 159.6 against 168.8) and adds nothing elsewhere over black; strength 0.3 changes the grey plate by 31.6 levels against 46.3 at 1, the plate stays within 2 levels away from the reflection, and the Hero level reflects the same pixels (IoU 1.000). A folded catcher set fails the shot. Splats stay out of the mirror, and geometry under the plane is not clipped.
  - Slice 13 (2026-11-06): the camera solve from footage. `crates/director-track` tracks Shi-Tomasi corners with pyramidal Lucas-Kanade (bicubic, a 0.5 px forward-backward check, affine correction against each track's first appearance), starts the scene from the essential matrix or the homography of the pair with the most parallax, registers each further frame by PnP, triangulates new tracks past 1.5 degrees and refines every camera, point and optionally the focal length with a Huber bundle adjustment over a Schur complement; the dominant ground plane then sets the world and frame 0's camera height the scale. On `solve.mp4` (60 frames at 480x270 from `make_solve.py`) it reprojects at 0.275 px rms against Blender's true cameras within 0.045 m and 0.066 degrees, the ground grid within 0.50 px, in 1 to 1.3 s, and refines a 36 degree guess to 41.928 against the true 42. `<model track="plate.mp4">` solves at compile time and films the model through the footage frame on show; over its plate the box overlaps Eevee's at IoU 0.92 to 0.93 and the shadow at 0.87 to 0.89 with the lens fixed or solved, the error near them drops from 64 to 68 levels for the bare plate to about 10, and the plate elsewhere moves 0.73 levels. The scene document keeps the solved cameras and renders the live frame. On real footage (16 s of AeroFlix 4D's CC BY 4.0 drone shot from archive.org, 854x480 at 25 fps) the first solve folded the scene: up to 70 frames apart the wrong relative pose held as many tracks as the right one. The start pair now needs one pose to stand out, which starts from frames 0 and 46, and the bundle passes while frames register move only the latest 24 cameras. The drone then flies a straight, level path at 6 m/s, 0.308 px rms over 1871 points, solved in about 14 s after 5 s of tracking (the incremental phase fell from 65 s to 1.4 s), and extruded type over the plate stays on the ground for the whole shot. The lens is close to unobservable on that straight flight (guesses of 30, 40 and 55 degrees end at 30.0, 40.0 and 49.7), so such footage needs `track-fov`.
  - Slice 14 (2026-11-06): lens distortion. The solve models Brown radial distortion (k1, k2) on focal-normalized coordinates and the bundle refines it beside the focal length. Freed on a pinhole plate, k1 of -0.005 moved the path 0.21 m, so the solve keeps the distortion only when it cuts the rms below 0.9 of the pinhole's. `make_solve.py --lens` renders the walk through a wider pinhole and resamples it into a k1 -0.15, k2 0.03 lens. At the true field of view the solve finds k1 -0.156 and k2 0.038, whose bend lands within 0.24 px of the true lens out to the corner, at 0.237 px rms and within 0.094 m and 0.25 degrees of the true path (the true lens held fixed gives 0.10 m). `solve.mp4` and the drone clip keep the pinhole. A tracked model with distortion renders through a wider pinhole at the same pixel focal length, and a Skia shader bends it into the lens as it paints; over the distorted plate the box overlaps Eevee's at IoU 0.905 to 0.932 and the shadow at 0.83 to 0.84, where a pinhole composite on the same plate reaches 0.31. `track-distortion` fixes k1 and k2 and the scene document keeps them.
